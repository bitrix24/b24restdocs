# Unlink Child Templates v 3.0 tasks.template.relation.child.delete

{% note tip "" %}

Choose a tool for developing with an AI agent:

- use [Alaio Vibecode](../../../../ai-tools/vibecode.md) to build an app for Bitrix24 from a task description without knowing any programming language. The agent writes the code and deploys the app to a server, with no manual hosting setup
- use the [MCP server](../../../../ai-tools/mcp.md) to develop a REST API integration in your own project. The agent refers to the official REST documentation

{% endnote %}

> Scope: [`tasks`](../../../scopes/permissions.md)
>
> Who can execute the method: an administrator or a user with permission to edit each template being unlinked and permission to read its parent template

{% note info "" %}

This method belongs to REST 3.0. The call specifics and response format of the new API version are described in the [REST 3.0 overview](../../../rest-v3.md).

{% endnote %}

The method `tasks.template.relation.child.delete` unlinks templates from their parent templates; the templates themselves are not deleted.

## Method Parameters

{% include [Note on required parameters](../../../../_includes/required.md) %}

#|
|| **Name**
`type` | **Description** ||
|| **templateIds***
[`integer[]`](../../../data-types.md) | Array of identifiers of the child templates to unlink from their parent. Pass from 1 to 20 unique identifiers; the method ignores duplicates.

Child template identifiers can be obtained using the [tasks.template.relation.child.ids](./tasks-template-relation-child-ids-rest-v3.md) or [tasks.template.relation.child.list](./tasks-template-relation-child-list-rest-v3.md) method ||
|#

{% note info "" %}

You do not need to pass the parent template: each template from `templateIds` is unlinked from its current parent. If a template has no parent template, the method returns `true` without an error.

{% endnote %}

    from b24pysdk import Config
    from b24pysdk.errors import BitrixSDKException

    method = "tasks.template.relation.child.delete"
    Config().configure(api_v3_methods=Config().api_v3_methods | {method})

    try:

            prefer_version=3,

            f"message: {error.error.message}",
            sep="\n",
